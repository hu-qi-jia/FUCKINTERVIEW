FUCKINTERVIEW 0.0.4：ASR 配置按供应商拆分，接入千问实时语音识别，并把「开始面试」的连接等待压下来。

## 安装

下载 `FUCKINTERVIEW-Setup-0.0.4.exe` 双击安装。首次启动会让你选**数据目录**和**模型目录**（可跳过，之后在「设置 → 通用设置」里改），然后在「设置 → 模型配置」填入 ASR / LLM 的 API Key 即可开始。从 0.0.3 升级会保留原有配置，ASR 的 Key、地址和模型会自动迁移到新的按供应商结构里。

## 这一版更新

**千问实时语音识别**

- 新增 `qwen3-asr-flash-realtime`（WebSocket，音频流式）：说话过程中就出部分文字，一句话结束到最终稿约 **0.1–0.3 秒**
- 设置里选到实时模型时自动带出官方地址 `wss://dashscope.aliyuncs.com/api-ws/v1/realtime`
- 实时 WebSocket 在后台连接，不阻塞面试开始；握手期间的音频先缓冲，连上后按顺序补发

**启动面试更快**

- 主进程启动时预取屏幕源，点「开始面试」直接复用，不再每次重新枚举
- 同一台机器实测：屏幕源准备 2.39s → **0.59s**，整段连接 5.78–7.48s → **1.43s**

**ASR 配置**

- 每个供应商单独保存一份 `api_key / base_url / model / language`，切换 MiniMax / Qwen / Deepgram / OpenAI 不再丢配置
- 模型改成下拉（保留「自定义模型」），切换模型自动填对应请求地址
- 显示能力标记：音频流式 / 结果流式 / 整段识别
- 旧版平铺配置读取时自动迁移，Key 不丢

**修复**

- 面试进行到约 5 分钟时被 Pipecat 空闲超时自动取消：已关闭空闲自动结束，生命周期只由客户端连接决定
- 教练面板里手动填的回答没点「保存」就切格或写回会丢：现在切格/写回前自动落盘
- MiniMax 分段识别 30 秒超时堵住串行队列：超时压到 10 秒，连接类错误且未吐字时重试一次，错误日志带异常类型
- 千问兼容接口返回异常 JSON 时只显示 `'choices'`：现在会带出响应内容

**首页**

- 顶部主视觉换成解密动效，文案 `FUCKINTERVIEW`，字号 30px

## 已知限制

- 千问实时 WebSocket 的断线重连和失败自动降级尚未实现：连接失败会报错，需要手动切回文件模型
- 实时识别目前只实测了中文，英文待补
- `qwen-audio-*-realtime` 这类 Omni 模型不走这套 ASR 实时协议；请选 `qwen3-asr-flash-realtime`

## 系统要求

Windows 10 2004 及以上（实时面试依赖 Windows 环回音频）。
